本文档按当前机器上实际可访问的目录，说明项目的代码位置、数据集组织方式和研究任务。当前工作区 `C:\Users\zj\Documents\三轴长尾场景识别` 主要保存项目审计材料、文献资料和数据可视化脚本；大体量训练代码和 MAT 数据位于 `E:\LJQ_code`，没有复制到当前工作区。

## 一、项目要解决的问题

项目面向雷达复合干扰的多标签识别。每个样本可以同时包含多个干扰分量，模型需要从一条复数 I/Q 脉冲中判断六类干扰是否存在，并在需要时估计活动分量的物理参数。

核心研究条件包括：

- **多标签组合识别**：六类标签允许以全部非空组合出现，共 `2^6-1=63` 种组合。
- **长尾分布**：通过标签频率、组合频率和功率可见性等轴构造不均衡数据，重点观察弱类和稀有组合的召回、误报及组合级准确性。
- **功率不均衡**：九挡配对数据改变不同干扰组的 JNR，研究跨功率条件下的识别稳定性。
- **弱分量可观测性**：MFT、VFT、ISRJ 等分量可能被更强分量遮蔽，实验需要区分“模型没有学到”和“输入中缺少可识别证据”。
- **参数感知**：对活动分量的 JNR、时延、周期、频移、假目标数、采样宽度等参数进行辅助估计；无效参数位置由 `parameter_mask` 标记，不能把无效 NaN 当作零值参与回归。
- **证据边界管理**：开发集、校准集、诊断测试和锁定测试分开管理；九挡功率视图共享身份时按配对视图处理，不能把它们简单相加为独立样本。

数据规模和标签契约：

| 项目 | 内容 |
|---|---|
| 标签顺序 | `[FMB, SawFM, SinFM, MFT, VFT, ISRJ]` |
| 非空组合 | 63 种 |
| 每组合样本数 | 400 |

主要 MAT 字段：

| 字段 | 含义 |
|---|---|
| `iq_complex` | 原始复数 I/Q，约为 `25200×3000` |
| `data_legacy` | 兼容旧代码的实数表示，包含实部和虚部 |

| `parameter_values` | 参数真值矩阵 |
| `parameter_mask` | 参数是否对当前样本和分量有效 |
| `manifest` | 组合、样本种子、分量种子和 split 元数据 |
| `parameter_schema` / `metadata` | 参数列定义、生成配置、版本和注册表信息 |

六类基础干扰的物理含义可概括为：FMB（频率调制阻塞）、SawFM（锯齿扫频调制）、SinFM（正弦调频）、MFT（多假目标）、VFT（速度/多普勒调制）和 ISRJ（间歇采样转发）。

### 2. 九挡功率配对数据

目录：

```text
E:\LJQ_code\干扰数据\复合干扰数据0716\power_sweep_9level_v1
```

挡位为 `10, 15, 20, 25, 30, 35, 40, 45, 50 dB`。每个挡位包含一个 train 和一个 test MAT 文件，仍然覆盖 63 个组合、每组合 400 条。

功率设置为：

| 干扰组 | 九挡设置 |
|---|---|
| FMB / SawFM / SinFM | 全部固定 30 dB |
| MFT / VFT / ISRJ | 按挡位从 10 dB 到 50 dB 变化 |

九挡之间对同一 split 和同一 `sample_id` 保持组合、物理参数、分量种子和 `receiver_noise_seed` 配对，只改变功率。因此九挡适合分析功率方向变化和配对差异，不应计作九批独立样本。

## 四、训练任务与评价指标

### 1. 主任务

给定长度 3000 的复数 I/Q 输入，输出六维 multi-hot 预测：

```text
FMB, SawFM, SinFM, MFT, VFT, ISRJ
```

模型既要保持整体 macro 性能，也要关注弱标签、稀有组合和低功率条件。常用指标包括每类 AUROC/AUPR、召回率、FPR、F1、Hamming loss、组合级 exact accuracy、稀有组合准确率和按功率分层指标。

### 2. 辅助参数任务

对活动分量回归物理参数，例如：

- FMB：实际带宽或带宽因子；
- SawFM：扫频周期、扫频带宽；
- SinFM：中心频率、频偏和调制频率；
- MFT：假目标数、时延和相对幅度；
- VFT：多普勒频移；
- ISRJ：采样宽度和转发副本数。

参数损失只在 `label=1`、`parameter_mask=1` 且目标值有限的位置计算。

### 3. 实验角色和测试边界

训练、早停、校准、阈值选择和开发/诊断数据需要在 manifest 中显式区分。配置中的 `allow_locked_test=false` 是默认安全边界；锁定测试只能在冻结策略后一次性使用，不能用来反复调参。历史报告中的 smoke、development、diagnostic test 和 locked test 结果也必须按证据角色分开解读。
