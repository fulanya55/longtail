# P3o-D：冻结时频识别与延迟峰参数残差的正式开发失败

P3o-D 在全新 1070M/1080M 身份上完成了三种子正式开发，但必须冻结为失败。训练/开发各 2,079 identities，交叉及历史身份重叠为零；未生成、打开或使用 test/locked test。

核心安全不变量失败：侧支训练时调用 `model.train()`，使被冻结 F 主干内的 BatchNorm 运行统计更新。因而候选与基线的分类 logits 三种子均不再 bitwise 相同，不能声称参数侧支不影响识别。这个问题即使参数 NMAE 变好也使该方法论证失效。

| Seed | Base Recall | Base 25 dB Recall | oracle NMAE（Base→Side） | predicted-gate NMAE（Base→Side） | worst-combination（Base→Side） |
|---:|---:|---:|---:|---:|---:|
| 2041 | 0.9435 | 0.8638 | 0.4553→0.4349 | 0.4481→0.4264 | 0.7395→0.7596 |
| 2042 | 0.8305 | 0.6330 | 0.4510→0.4340 | 0.4413→0.4250 | 0.7606→0.8008 |
| 2043 | 0.9219 | 0.8201 | 0.4529→0.4333 | 0.4458→0.4255 | 0.7728→0.7715 |

另有两项晋升失败：F 基线在 2042 未达到总体/25 dB 识别门槛；侧支的 worst-combination NMAE 在 2041/2042 恶化。因此不使用 1090M/1100M 确认身份，也禁止在 1080M 修复重跑。

后续若提出新侧支机制，必须使用全新 identity seeds，且在正式数据生成前的单元测试中验证：调用 `train()` 后 F logits 逐位一致、所有 F BatchNorm buffer 不变；并保留最坏组合不恶化作为独立门槛。
