# B3-R 统一物理前端与速度优化执行报告

## 结论

B3-R 已在 5 个固定开发种子、3 个代表功率点（10/30/50 dB），共 15 个点上通过确认门槛。该版本不改变 B2-RC 的模型、阈值或路由数学，只将推理实现重构为单次读取、单次归一化、单次传输，以及 GPU 上共享的物理特征计算。

locked test 未读取，E5 保持冻结。

## 优化过程与失败原因

### B3-0：仅共享 FFT

- batch=128 时，总延迟估计为 E5 的 1.970 倍，未通过。
- batch=512 时，总延迟估计反而升至 E5 的 2.227 倍，未通过。
- 原因：虽然 MFT/ISRJ 共享了 FFT，但 E5 与物理专家仍各自读取数据、归一化和传输，流水线没有真正统一；盲目扩大 batch 还增加了调度和内存开销。

### B3-R1：统一读取与 CPU/GPU 重叠

- 首版 HDF5 fancy indexing 单次读取约 14--15 秒，掩盖了计算优化收益。
- 改成逐列连续读取后，读取时间降至约 0.47--0.55 秒。
- 但物理特征仍主要在 CPU 上计算，同运行 E5 的平均计算倍率为 1.582，仍未通过 1.5 倍门槛。

### B3-R2：全 GPU 统一前端

最终流水线为：

1. HDF5 只读取一次 I/Q；
2. 只执行一次归一化和主机到 GPU 的传输；
3. 在 GPU 上并行完成 EfficientNet-B1、VFT 分支以及 MFT/ISRJ 共享物理特征；
4. 仅把低维物理特征送回 CPU 的树模型和三状态路由器；
5. 保留 B2-RC 的固定 E5 MFT 阈值、recall 约束和 `unknown_keep_E5`。

## 验证与审计边界

- 完整单元/回归测试：50 passed。
- 本轮仅使用开发与内部验证数据，没有读取 locked test。
- 本轮没有重新选择阈值、专家超参数或路由参数。
- 速度结论来自同一进程、同一设备、同一数据路径的成对计时；端到端 E5 基准包含相同的读取和归一化成本。
- 10/30/50 dB 用于工程确认；B2-RC 的九功率识别收益仍以既有九功率结果为准。

## 下一决策门

按既定路线，下一阶段进入 B4：匹配困难负样本。B4 应冻结本轮统一前端，只改变困难负样本的构造与训练采样；若不能在不损伤 MFT/ISRJ recall 的条件下继续降低同组合诱发的假阳性，则停止扩大专家容量，转向 B5 的三状态有界路由消融。
